# C004 — Structured flow, PROC, FN and LOCAL

This task defines structured execution and activation semantics beyond the
bootstrap's GOTO/GOSUB subset. PROC, FN and LOCAL are currently rejected.
Conditional implementation and differential qualification are active.

## Identity, status and dependencies

1. Immutable ID: **C004**. Status: **active — conditionals, loops and scalar PROC/LOCAL promoted; FN pending**.
2. Origin: the Author explicitly requires separate procedures, functions and
   other control-flow constructs, with LOCAL restoring previous values.
3. Dependencies: [C002](C002.md) for expressions and [C003](C003.md) for
   bindings/string ownership; [C001](C001.md) supplies basic native branching.
   The reference audit identifies parser/stack coupling in interpreter routines.

## Scope

1. Define and implement the selected conventional conditional and loop forms,
   including nested control flow and compile-time structural diagnostics.
2. Define distinct PROC/FN activation records, parameters, recursion and
   matching exits. Preserve function return values and procedure behavior.
3. Save previous LOCAL bindings and restore them in reverse order, including
   numeric values, strings, recursion and later error unwinding. Establish the
   exact behavior against the reference, including any existence/type state.
4. Define label scope and reject branches that violate activation boundaries.
   Do not lower PROC/FN to unchecked GOSUB or replace dynamic LOCAL behavior
   with unrelated C-style lexical locals.

## Acceptance criteria

1. Differential tests cover each enabled structured construct, nested forms,
   false/true conditions and boundary/error cases.
2. Recursive PROC/FN tests preserve arguments, results, outer bindings and
   strings, and reject mismatched exits or unsafe cross-activation branches.
3. LOCAL tests demonstrate prior-value restoration on normal return and every
   enabled unwind path, including nested calls observing installed locals.
4. Activation ABI, label scope, ownership and supported unwind behavior are
   documented, with unsupported forms clearly diagnosed.

## Loop tranche definition

1. After qualified conditionals, add REPEAT/UNTIL, WHILE/ENDWHILE and numeric
   FOR/TO/STEP/NEXT. Conditions use the same reference SFIX truth conversion.
   FOR evaluates initial/limit/step in order, enters its body at least once,
   and preserves variable-type conversion, comparison direction and errors.
2. Audit EXEC.Z80 REPEAT/UNTIL/FOR/NEXT/WHILE/ENDWHI/RETURN and RESLOC. Loop
   markers must be distinct from GOSUB and subsequent PROC/FN activation records;
   recursive entries must never overwrite static per-site limit/step storage.
3. Define a bounded typed runtime control stack with explicit ownership and
   checked entries/exits before coding. Branches to unsupported control/activation
   boundaries must fail clearly, not silently bypass required runtime markers.
4. Same-source qualification must cover zero/past-limit starts, integer/float/
   byte variables, positive/negative/fractional/zero steps (bounded by explicit
   exits), evaluated-once limits, nested loops/calls, missing markers, runtime
   errors/evaluation order, determinism and prior regressions. Freeze/promote
   qualified code and record exact evidence. Experiments belong in C004/loops.
