# C005 — Arrays, indirection and bootstrap I/O — DRAFT

This task closes the remaining language facilities needed to compile the
compiler source itself. The current BASIC-hosted compiler uses arrays, file
operations and byte indirection that its generated programs cannot yet use.
No implementation has begun under this ID.

## Identity, status and dependencies

1. Immutable ID: **C005**. Status: **planned; not started**.
2. Origin: the Author's self-hosting requirement; the bootstrap source gives a
   concrete initial inventory of required facilities.
3. Dependencies: [C002](C002.md), [C003](C003.md) and [C004](C004.md) for
   numeric, memory, binding and activation contracts; the MOS audit in
   [REFERENCE.md](../../compiler/REFERENCE.md) informs I/O integration.

## Scope

1. Inventory every construct in the chosen compiler source and identify gaps
   explicitly before claiming bootstrap closure.
2. Implement required arrays/DIM and byte/word indirection with defined
   dimensions, element widths, bounds and ownership. Preserve BASIC integer
   width independently of ADL pointer width.
3. Implement required text/binary file operations and interactive input using
   documented MOS APIs and tested EOF/error/close behavior.
4. Address any remaining required operations through the same explicit
   inventory and task refinement. Keep EVAL excluded and reject unsupported
   language forms rather than silently falling back to interpretation.

## Acceptance criteria

1. The compiler-source inventory maps every required construct to an
   implemented feature and a meaningful test, with no unreported gaps.
2. Array/indirection tests cover representation, addressing, boundary failures
   and enabled LOCAL/recursive array behavior.
3. File tests cover empty/binary/text inputs, EOF, line endings, open/write
   failures, resource cleanup and generated executable output.
4. Generated programs exercise the actual MOS path and preserve the reference
   semantics for each enabled facility; the compatibility matrix is updated.
