# C001 — Runtime investigation and native bootstrap experiment

A small compiler written in BBC BASIC successfully generated and ran native
Agon executables. Its automated qualification passed, including error cases
and an independent assembly comparison. The code was promoted to `compiler/`
on 2026-11-01 after repeat validation. General numeric/string semantics and
self-hosting are not implemented.

## Objective, scope and acceptance criteria

The experimental objective is to prove that BBC BASIC can parse a small text
program, resolve symbols, emit a standalone MOS ADL image and execute it on an
eZ80 backend without dispatching the source through an interpreter at runtime.

1. The compiler implementation is BBC BASIC. Linux/Python may prepare and
   check tests but cannot implement parsing or code generation for it.
2. Generated images carry the MOS header, use 24-bit native addresses and
   return safely to MOS with observable success/error status.
3. The subset demonstrates unnumbered/numbered source, named/forward targets,
   literal PRINT, byte VDU, CLS, REM, GOTO, checked GOSUB/RETURN and END.
4. Malformed or unsupported input is diagnosed at compile time. Existing
   output survives source/relocation errors. EVAL is excluded explicitly.
5. Actual BASIC-hosted compilations and native executions pass; repeated
   compilation is deterministic, and one complete image matches an independent
   GNU assembler oracle byte for byte.
6. Research records identify numeric representations, routine calling
   conventions, interpreter state dependencies, licensing and relevant tools.
   Unsupported semantics remain explicit in the compatibility matrix.

These criteria define the original experiment. Its subsequent live promotion
and repeat qualification are recorded separately below.

## Investigation and implementation record

1. Inspected the local BASIC V ADL baseline
   `2998edd4ceb6030d6840cb4e3d587e75d94dc44c`, including math, evaluation,
   execution, variables, RAM, startup, MOS glue, existing conformance sources,
   build configuration and license.
2. Searched the official Agon repositories/documentation and downloaded Dean
   Belfield's ADL source into `/tmp/bbc-compiler-reference`, pinned to
   `3901c2de520c3e9f96ad6f5f0ad9aaec3663e65f`. Inspected its arithmetic,
   strings, variable handling, procedures, LOCAL, allocation, MOS integration
   and licensing. The durable audit is [REFERENCE.md](../../compiler/REFERENCE.md).
   No interpreter routine was extracted or linked into generated images.
3. Compared the ZDS II source format, AgonDev GNU build and native ez80asm
   option. Consulted official local `mos/API.md`, `mos/Executables.md`,
   `Programming.md` and `BBC-BASIC-for-Agon.md`. Direct byte emission avoids a
   target assembler dependency for this experiment; GNU tools independently
   check the emitted bytes.
4. Implemented a numbered BBC BASIC bootstrap with plain-text line reading,
   lexical helpers, literal decoding, statement parsing, a symbol table,
   absolute 24-bit fixups and binary file writing. Proposed `@name:` labels
   with explicit `GOTO @name` / `GOSUB @name` targets. Full behavior/limits are
   described in the draft [specification](../../compiler/SPECIFICATION.md).
5. Implemented a small new runtime for inline length-prefixed literal output,
   MOS character/stream calls, checked GOSUB depth, RETURN errors and stack
   restoration on END. BASIC language integers/floats are not implemented by
   this address-oriented runtime; no 24-bit numeric substitution is claimed.
6. Added `hello.bas`, an independent assembly fixture and a Python driver
   harness. The harness combines BBC BASIC entry code with the actual compiler
   definitions, invokes the reference interpreter and checks generated images.
   It does not translate or compile BASIC itself.
7. Built the unmodified local interpreter using the installed ARM64 AgonDev
   assembler/linker. Existing ez80asm and Fab CLI binaries were x86-64 on this
   ARM64 host, so built the unchanged official Fab 1.2.5 CLI source using
   Cargo's locked offline dependencies and an isolated output directory at
   `/tmp/bbc-compiler-cli-target`. Upstream sources were not modified.
8. Generated the ignored project `.emulator/` fixture with canonical setup
   helpers, retained the generated launcher and verified the pinned MOS 3.0.2
   image/map. Used the text-only CLI backend via that wrapper. Its unused
   firmware-option warning and minimal fake-VDP startup messages are retained
   in the logs. This fixture is not a graphical review instance.

## Debugging and experimental findings

1. Initial literal parsing failed after a nested single-line conditional.
   Reworked quote handling into separate conditions; later tests cover doubled
   quotes, empty strings and quoted colons.
2. A symbol-search FN attempted to return with a FOR frame still active and
   reported `Not in a FN`. Reworked it to finish its loop before returning.
   This is an observed bootstrap-host failure, not a blanket claim about every
   BBC BASIC implementation.
3. Colon consumption initially checked the next statement as unexpected text.
   Corrected statement-boundary handling, including same-line named labels.
4. Guarded empty-literal emission and symbol-table reuse; tested repeated
   compilations rather than relying on fresh interpreter state.
5. An early smoke probe stopped when the output file first existed, before
   writing finished. Final qualification waits for completion markers after
   close; existence alone is not used as evidence of a complete executable.
6. The independent oracle initially encoded an error-message length as 14
   instead of 15. Correcting the fixture produced byte-for-byte equality with
   the compiler's image without a compiler change.
7. A native runtime error correctly returned 1 and stopped MOS autoexec.
   The final harness uses MOS `Try` and checks `Try$ReturnCode` for every image,
   testing both error and success paths without aborting the remaining cases.

## Recorded qualification and limits

1. Original qualification: **39 compiler cases**, **15 native executions**,
   including **24 compilation-error/output-preservation cases**. All passed.
   A further compilation of the same input produced identical bytes; one
   complete output matched the assembler oracle. Runtime errors returned 1
   and normal programs returned 0 to MOS.
2. Original duration: **13.043 seconds**, excluding setup/build. The emulator
   used unlimited CPU speed; this is a functional test duration, not hardware
   performance. Exact input hashes are retained in
   [the original report](C001/evidence/qualification-001/results.json).
3. The relocated harness changes only project/task path resolution. Its fresh
   qualification again passed **39 cases and 15 native executions** in
   **13.155 seconds**, with the same qualified input hashes, deterministic
   repeat and assembler match. See
   [qualification-002](C001/evidence/qualification-002/results.json). The
   relocation manifest proves the compiler, sample and oracle did not change
   and that reversing only the harness's path edits reproduces its old hash.
4. Human graphical review, physical Agon execution, performance qualification,
   numeric/string runtime compatibility and self-compilation remain unproven.
   The [compatibility matrix](../../compiler/COMPATIBILITY.md) describes the
   experiment's limits. Tests do not authorise emulator-related commits.
