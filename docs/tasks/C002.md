# C002 — Numeric runtime and expressions

This task owns numeric compatibility work. The reference arithmetic package,
pointer adapter, native expressions, standard math functions and default PRINT
are in the development tree. The Author rejected deliberate decimal-reader
improvements; corrected reference conversion and identical-source qualification
are now accepted for the development checkpoint. Earlier closure and exact-conversion reports below
are historical and do not establish compatibility acceptance.

3. Inputs: [C001](C001.md), its tested code-generation path, the

## Scope

The Author clarified that execution speed is the only intended observable
runtime difference, then authorized retaining interpreter improvement ideas
separately. Earlier decimal-reader corrections and arithmetic-substitution
oracles are rejected as compiler semantics. Their reports remain historical.
This correction replaces the exact converter with reference conversion, removes
substitute literal oracles (including the earlier 2^32 exception), compares
packed values and output against the same source in actual BASIC, and retains
possible upstream improvements in `compiler/INTERPRETER-FINDINGS.md`.
Existing unsupported-feature/capacity diagnostics stay explicit. No interpreter
patch or upstream submission is authorized by this correction. The later
explicit commit/push request authorizes the development checkpoint.
Numeric reader errors must occur when the atom executes, including preservation
of unreachable-code behavior. Audit emitted numeric diagnostics against the
reference's actual message table and REPORT$, not arithmetic-package comments.

1. Select a pinned numeric package, document its license and retained notices,
   and adapt its register, stack and error conventions behind an explicit ABI.
2. Implement exact integer/float storage, numeric constants, conversion,
   arithmetic and comparisons. Define promotion, signedness, evaluation order
   and assignment conversion from the reference, not host language shortcuts.
3. Keep 24-bit addresses distinct from four-byte language integers. Do not
   substitute IEEE floating point or wrap every integer intermediate silently.
4. Keep unsupported operations diagnosed until individually qualified. EVAL
   remains outside the initial implementation.

## Acceptance criteria

1. Storage and conversion fixtures match the reference's byte representations
   for zero, signed boundaries, fractional values and exponent extremes.
2. Differential tests cover mixed arithmetic, promotion/overflow, truncation,
   comparisons, division by zero and other enabled numeric error paths.
3. Adapter tests exercise ordinary/alternate registers, ADL memory widths,
   stack restoration and error exits in standalone generated programs.
4. Runtime provenance, supported operation table and calling convention are
   recorded; the specification/matrix reflect only tested operations.

## Experiment and promotion record

1. Implemented `C002/numeric.s` with the packed-value pointer ABI described in
   [ABI.md](C002/ABI.md). The exact reference math source/license are retained
   initially under `C002/vendor/`; [provenance](../../compiler/runtime/vendor/PROVENANCE.md) identifies
   hashes, source revision and adaptations. Runtime source is assembly; the
   compiler itself remains BBC BASIC.
2. Initial standalone assembly found required UEXT/UEXTA compatibility macros.
   Standalone linking then found undeclared DLOAD5_SPL / STORE5_SPL imports,
   beyond the declared STORE5 / DLOAD5 / TEST helpers. Supplied all helpers
   explicitly, using byte-exact accesses for packed and sparse layouts. The
   final numeric object has zero unresolved symbols and occupies 3812 bytes.
3. Implemented a BASIC reference generator and native probe in
   `C002/tools/test_numeric.py` and `C002/probe.s`. The reference interpreter
   supplies all packed numeric inputs and expected results. The native probe
   executes the extracted package and exposes status/results plus structural
   checks; Python only generates descriptions, builds and compares records.
4. Initial differential qualification passed 253 cases. Strengthening it with
   explicit precision/tie vectors caught incorrect fixture assumptions about
   exponent encoding and ties-to-even rounding; the runtime did not change.
   FONE confirms exponent 128 for 1.0, and ODD selects an odd low significand
   bit for exact halfway cases. The final byte anchors record BBC behavior.
5. The strengthened fixture also exposed a reference constant-reader
   discrepancy: `4294967296.0` is stored as `FA FF FF 7F 9F`, whereas the
   exactly constructed `2147483648.0*2` is `00 00 00 00 A0`. Preserve this as
   an observed parser defect, not a compiler compatibility promise. Use exact
   arithmetic construction for rounding tests. The observations and original
   oracle source are retained under `C002/evidence/precision-fixture-001/`;
   the initial tie observations are under `precision-fixture-002/`.
6. Final automated qualification passed **257 cases** with **zero numeric or
   ABI mismatches**, including four explicit precision/rounding anchors,
   pointer/stack preservation, operand aliasing, adjacent canaries, unchanged
   right operands and input preservation on failure. Status counts were 239
   successes, six rejected selectors, one division-by-zero error, ten Too-big
   errors and one Log-range error. The run took **15.574 seconds**, including
   reference execution, assembly/linking and native execution; provisioning is
   excluded and unlimited-speed emulation is not hardware timing.
7. Retained selected source, fixture, logs, result report and environment
   identities in [qualification-001](C002/evidence/qualification-001/results.json).
   The comparison qualifies extraction/calling compatibility with this
   interpreter, not independent mathematical correctness of all package code.
8. At the end of the adapter tranche, no numeric runtime had been promoted or
   emitted by the live compiler. C002 remained open for constant/expression parsing, numeric code emission,
   runtime placement/relocation and integration tests. A packed pointer ABI is
   now available for that work; expression/value-stack policy is not silently
   settled by this experiment. Open work remains in [TODO.md](../../TODO.md).
