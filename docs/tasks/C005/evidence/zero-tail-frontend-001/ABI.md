# Compact native call-adapter contract

These adapters share repeated eZ80 register setup and checked runtime calls.
Every site remains an actual native CALL with a fixed operand layout; there is
no source parser, bytecode loop or instruction-stream dispatch engine. The BBC
compiler chooses each entry and writes its operands. Arithmetic/conversion,
array ordering and activation semantics stay in the previously qualified modules.
The394-byte/29-relocation runtime passes21 native ABI stages and the isolated
2f81c6fb frontend integration. GNU links independently match at&42000/&48000.

## Operand and result contracts

All addresses are little-endian24-bit ADL pointers. Slot indices are trusted
compiler-generated bytes0..31. Numeric slots are five bytes; string slots256.
The caller return address advances over the fields shown, including on an error
transfer. Each external error bridge owns the ordinary compiled error path.

| Entry | Fixed bytes after CALL | Result / compatibility |
| --- | --- | --- |
| cp_literal | slot:u8, packet:5 | Set IX to the numeric slot; tail-call unchanged NUM literal entry, which consumes the packet; preserve IY |
| cp_numeric | lhs:u8, rhs:u8, operation:u8 | Set IX/IY to those numeric slots; call unchanged NUM; transfer carry/A to numeric error bridge |
| cp_read1/4/5 | binding:u24, slot:u8 | Test binding flag first; copy exactly1/4/5 payload bytes and zero-fill the rest of the five-byte numeric slot; preserve original IX/IY; missing binding transfers to No such variable |
| cp_store1/4 | destination_payload:u24 | Apply unchanged SFIX operation38 to v0 first; preserve destination and width across NUM; transfer error before any destination write; copy low1/4 bytes on success; IX/IY end at v0 |
| cp_store5 | destination_payload:u24 | Copy all five v0 bytes; preserve IX/IY; AF is volatile and carry is unspecified |
| cp_arrayprefix/addr | array_pointer_cell:u24, subscript_slot:u8, width:u8, count:u8 | Set the original IX/IY/B/A inputs, call unchanged memory helper, preserve its result and early failure; no new combined indexing semantics |
| cp_actsave | binding:u24, type:u8 | Same IX/A as old save; capture still precedes actual evaluation; checked ACT error transfer |
| cp_actbind | record_offset:u8, kind:u8, slot:u8 | kind0 numeric /1 string; same A/IY as old bind; reverse binding order remains a BBC frontend decision |
| cp_actbegin | none | Checked wrapper around unchanged ACT begin; no CPU-stack-relative operand is introduced |

1. BC/DE/HL/AF are volatile unless specified. Every successful entry balances SP;
   read entries also restore IX/IY. Integer/byte destination creation still occurs
   in the frontend before RHS evaluation, as before. Stores never truncate a
   conversion failure into a value. No32-bit integer or40-bit float is replaced.
2. Error transfers discard all internal register saves first. They retain only
   the advanced caller continuation; actual error handling restores its captured
   CPU/control/arena context. ABI probes may replace a terminal bridge with a
   returning observation stub to prove that balance without invoking a handler.
3. Keep the existing four-byte err_line entry and its qualified WHILE/FN/held-key
   attribution. This prototype does not add a second source-line mark adapter.

## Package and bridge fields

The fixed export header has13 callable entries in table order, followed by13
three-byte bridge fields: numeric base, string base, NUM operation, numeric error,
NUM literal, missing variable, array prefix, array address, memory error, ACT save,
ACT bind, ACT begin and activation error. Pointer cells are actual d24 fields;
other bridge fields are operands of private JP stubs. Internal references to
these cells/stubs remain ordinary PIC relocations, separate from bridge values.

The BBC template emitter must merge both sorted disjoint offset sets, as for
existing modules. Optional unused facilities may receive an explicit zero alias;
a call requiring that facility must enable it first. Source preparation/package
location is not proof that any entry or unused-zero combination is correct.

## Qualification boundary

Native probes must establish packet consumption/SP and index-register behavior,
upper-register poisoning, min/max slots, all copy widths, guard bytes, missing
bindings, real NUM operations, real SFIX success/overflow/store atomicity and
array/activation register/error bridges. GNU links independently establish PIC
rebasing and bridge-field separation. Then actual BBC differential programs
qualify frontend use, LOCAL/FN live prefixes, arrays, errors and fresh output fit.
Only exact passing sources may be promoted; actual native compiler fit remains
a separate resource measurement.
