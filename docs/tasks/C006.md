# C006 — Self-hosting and physical qualification — DRAFT

This task establishes that the compiler can compile its own BBC BASIC source
and that its generated native compiler works on Agon hardware. The present
bootstrap cannot do either; the earlier emulator tests do not satisfy this
task. No implementation has begun under this ID.

## Identity, status and dependencies

1. Immutable ID: **C006**. Status: **planned; not started**.
2. Origin: the Author's central requirement for a native compiler written in
   BBC BASIC and ultimately capable of compiling its own source.
3. Dependencies: tested, promoted facilities from [C002](C002.md),
   [C003](C003.md), [C004](C004.md) and bootstrap closure in [C005](C005.md).

## Scope

1. Run the BBC BASIC compiler source under the reference interpreter to emit
   a native compiler, then use that native compiler on its own source.
2. Repeat native self-compilation and compare deterministic outputs. Record
   source/runtime versions, build inputs, hashes and failure diagnostics.
3. Prepare and qualify a physical Agon fixture using the canonical deployment
   conventions; keep automated emulator, human review, hardware functionality
   and hardware performance conclusions separate.
4. Establish a reproducible live build/run workflow without a Python compiler,
   interpreter execution engine or substituted numeric representation.

## Acceptance criteria

1. A reference-interpreted compiler emits a functioning native compiler from
   the same BBC BASIC source, with no unsupported bootstrap constructs.
2. Native generations compile that source repeatedly with byte-identical
   deterministic output and pass the retained compiler/runtime regression suite.
3. Physical Agon execution demonstrates the compilation chain and generated
   program behavior, with exact artifact identities and operator evidence.
4. Any accepted size/performance claims identify hardware measurements and
   configuration rather than extrapolating unlimited-speed emulator timings.
