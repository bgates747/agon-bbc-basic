# C003 — Scalar variables and mutable strings

This task owns variable and string compatibility. The first tranche implements
scalar numeric assignment and reads, with reference naming, storage, conversion
and runtime existence. Mutable strings remain a subsequent C003 tranche.

## Identity, status and dependencies

1. Immutable ID: **C003**. Status: **active — scalar numeric bindings promoted; mutable strings pending**.
2. Origin: the Author requires BBC BASIC variable conventions and string
   semantics, including compatibility with LOCAL restoration.
3. Dependencies: [C001](C001.md) for native emission and [C002](C002.md) for
   numeric values/conversion. Inputs include the string/heap investigation in
   [REFERENCE.md](../../compiler/REFERENCE.md).

## Scope

1. Specify suffix-based types, unsuffixed numeric variables, name identity,
   initialisation rules and binding slots using the reference interpreter.
2. Implement mutable length-aware strings, empty values, assignment, copying,
   allocation, growth and resource-limit errors. Define ownership across
   expression temporaries, aliases and later procedure/local boundaries.
3. Specify heap bounds, stack separation and allocation failure behavior.
   Interpreter globals and allocation assumptions must be replaced or
   deliberately initialised, not called through arbitrary interpreter addresses.

## Acceptance criteria

1. Differential tests establish variable naming/type and assignment semantics,
   including numeric conversion and enabled undefined-variable behavior.
2. String tests cover empty/maximum length, embedded zero bytes, repeated
   reassignment, growth, self-assignment and source/destination independence.
3. Churn and exhaustion tests show defined memory behavior and clear failure;
   no descriptor corruption or unbounded accidental interpreter-style leaks
   are silently accepted as the runtime policy.
4. The ownership/binding contract supports the save/restore requirements of
   [C004](C004.md) and is recorded in the specification before promotion.

## Scalar numeric tranche definition — 2026-11-01

1. Pre-tranche checkpoint: `b20c377`, pushed to the existing development branch
   at the Author's explicit request. C002's reference-compatible numeric baseline
   is accepted for this checkpoint; Oryx remains unavailable.
2. Implement plain and LET assignment, reads in existing numeric expressions,
   and separate case-sensitive bindings for unsuffixed, `%` and `&` names.
   Keep each physical payload at the reference width: five, four or one byte.
   Unsuffixed values retain their integer/float record; `%`/`&` use SFIX and
   `&` stores the low byte. No new arithmetic or decimal representation.
3. Preserve runtime existence: uppercase single-letter `%` variables exist at
   zero, dynamic variables do not. Assignment creates its target at zero before
   evaluating the RHS. Reads check existence at execution time; skipped stores
   cannot create bindings. GOSUB shares the same global binding. No LOCAL/PROC/FN
   substitution or speculative default-zero reads.
4. Names use the compiler's current ASCII letter/underscore/digit, 32-character
   body limit. Conservatively reject keyword-prefix naming forms until their
   tokenisation is supported; do not reinterpret a BBC function as a variable.
   Reject strings, arrays, indirection, format/pseudo variables, compound
   assignment and unqualified suffixes clearly. Bound scalar bindings explicitly.
5. Keep compiler experiments and qualification under C003 before promotion.
   Reuse the unchanged numeric runtime, with BBC-written emission of byte-copy
   and existence checks. Each binding has an explicit existence byte separate
   from its physical numeric payload, suitable for later save/restore design.
6. Acceptance: actual BASIC supplies identical-source transcripts, runtime
   errors and packed storage expectations. Cover conversions/bounds, low-byte
   wrapping, integer/float preservation, case/suffix identity, creation ordering,
   static versus dynamic names, skipped assignment, GOSUB mutation, repeated
   compilation, limits and rejection preserving existing output. Independently
   check runtime relocation and preserve existing compiler regressions.
7. Promotion requires passing experimental evidence, byte-identical copying to
   the single live compiler, updated specification/matrix and live rechecks.
   Automated Pi5 qualification is separate from human/hardware acceptance and
   permission to commit new tranche work. No benchmark speedup is claimed.
