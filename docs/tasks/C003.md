# C003 — Scalar variables and mutable strings

This task owns variable and string compatibility. The first tranche implements
scalar numeric assignment and reads, with reference naming, storage, conversion
and runtime existence. The mutable string core is now also promoted; further
string operations/conversions remain unfinished.

## Identity, status and dependencies

1. Immutable ID: **C003**. Status: **active — bindings, string core, expression slices, comparisons and VAL/STR$/ASC promoted; further string operations pending**.
2. Origin: the Author requires BBC BASIC variable conventions and string
   semantics, including compatibility with LOCAL restoration.
3. Dependencies: [C001](C001.md) for native emission and [C002](C002.md) for
   numeric values/conversion. Inputs include the string/heap investigation in
   [REFERENCE.md](../../compiler/REFERENCE.md).

## Scope

1. Specify suffix-based types, unsuffixed numeric variables, name identity,
   initialisation rules and binding slots using the reference interpreter.
2. Implement mutable length-aware strings, empty values, assignment, copying,
   allocation, growth and resource-limit errors. Define ownership across
   expression temporaries, aliases and later procedure/local boundaries.
3. Specify heap bounds, stack separation and allocation failure behavior.
   Interpreter globals and allocation assumptions must be replaced or
   deliberately initialised, not called through arbitrary interpreter addresses.

## Acceptance criteria

1. Differential tests establish variable naming/type and assignment semantics,
   including numeric conversion and enabled undefined-variable behavior.
2. String tests cover empty/maximum length, embedded zero bytes, repeated
   reassignment, growth, self-assignment and source/destination independence.
3. Churn and exhaustion tests show defined memory behavior and clear failure;
   no descriptor corruption or unbounded accidental interpreter-style leaks
   are silently accepted as the runtime policy.
4. The ownership/binding contract supports the save/restore requirements of
   [C004](C004.md) and is recorded in the specification before promotion.

## Mutable string core tranche — 2026-11-01

1. Pre-tranche checkpoints: scalar support `4577673`, followed by build-ignore
   cleanup `c9f0b5f`, both pushed before implementation. Oryx remains unavailable.
2. Implement `$` bindings, plain/LET string assignment, independent copying,
   concatenation and parentheses, string PRINT, LEN and CHR$. Preserve runtime
   creation/undefined reads and the 255-byte limit. Embedded zeros are data;
   string/numeric mixing, slicing, VAL/STR$, comparison, arrays and LOCAL remain
   explicitly unsupported until qualified separately. Literal-only PRINT must
   retain its existing complete assembly golden.
3. Audit EXEC.Z80 STORES/STORE4STR and EVAL.Z80 LOADS/CHRS/LEN/string addition.
   Use the five-byte length/capacity/pointer descriptor, capacity reuse and tail
   extension, with native private allocator context rather than FREE/HIMEM/ACCS.
   Runtime routines are adaptations/new glue, not unmodified extracted entries.
   Preserve provenance and the repository's existing license.
4. String expression values use private 256-byte length-prefixed temporary
   buffers. Assignment copies from a completed temporary into owned storage;
   no two bindings share mutable contents. Parenthesised subexpressions keep
   separate values so evaluation/error ordering is preserved. LEN consumes a
   string item; CHR$ uses reference SFIX and low-byte conversion.
5. Reserve private heap workspace after the loaded image, below the Agon user
   RAM limit. Budget 1024 bytes per declared string binding: retained capacities
   grow monotonically to at most 255. Between non-tail reallocations, tail
   extension can increase the old block; the abandoned geometric growth series
   plus its live allocation remains below 768 bytes per binding. The 1024-byte
   budget leaves margin in this no-LOCAL/no-deletion tranche.
   The heap is runtime workspace, not zero-filled file data. Allocation checks
   precede descriptor/copy changes; empty strings never dereference null data.
6. Keep the numeric template/vendor unchanged. Build a separately relocatable
   string runtime, embedded as BBC DATA and rebased by the BBC compiler. Source
   parsing and code emission remain BBC BASIC; Python only packages assembled
   runtime bytes and orchestrates qualification. Experiments remain under C003.
7. Acceptance: compare the same conventional programs with actual BASIC,
   including empty/embedded-zero/max-length strings, aliasing, self-assignment,
   shrink/growth/copying, nesting/error ordering, LEN/CHR$ and undefined reads.
   Check physical descriptors/content, private heap and write guards; exercise
   overflow/allocation failure paths and growth churn with a native ABI probe.
   Require independent runtime links, deterministic compilation, output
   preservation on rejection, existing regression checks and live rechecks
   before promotion. New work stays uncommitted pending review.
